Capgemini OCM Skill Suite

16 conversational Claude skills for change practitioners. Ask in plain language — "build a CIA from these workshop transcripts" — and Claude gathers what it needs, extracts and validates the data, and renders client-ready deliverables: Excel workbooks, self-contained interactive HTML dashboards, and PPTX/Word documents. You never hand-edit JSON or touch a terminal.

Pipeline — how the skills chain

Raw inputs transcripts / interviews / workshop notes ▶ cia-builder cia_records.json + sha-builder sha_records.json
Downstream ▶ tom-vro-builder comms-toolkit change-network-builder adoption-metrics-builder readiness-pulse-builder persona-journey-builder ocm-playbook-builder ocm-readout-builder
Training chain training-strategy-builder ▶ training-needs-builder training_needs.json ▶ curriculum-architect curriculum.json ▶ training-content-builder + interactive-learning-builder ▶ training-rollout-builder

Skills chain through shared JSON files. Name alignment is the contract: CIA roles_impacted ↔ SHA stakeholder_group ↔ comms audiences[].name. Every skill also runs standalone and degrades gracefully when the upstream artifact is missing. Click any node to jump to its card.

Core OCM

The foundation: impact and stakeholder assessments feed everything downstream.

Diagnose cia-builder

Turns current/future-state transcripts into a Change Impact Assessment — 6 MECE Change Dimensions, severity×complexity scoring, scope disposition, optional TOM/Value/Training/Workshop layers, and an incremental update loop for new transcripts.

Produces
CIA xlsx + interactive HTML dashboard + cia_records.json (the suite's canonical change dataset)
Use it when
  • Workshop or interview transcripts are in and you need the impact register
  • New transcripts arrive and the CIA needs a refresh (merge, don't rebuild)
  • You're starting an engagement and want the anchor artifact everything else reads
Example ask
"Build a CIA from these workshop transcripts."
Needs
Current/future-state transcripts, interviews, or workshop notes
Feeds
tom-vro-builder, comms-toolkit, training-needs-builder, ocm-readout-builder, and every downstream skill that reads cia_records.json

Deps: openpyxl. Ships validate_chain.py.

Diagnose sha-builder

Turns interviews and stakeholder notes into a Stakeholder Assessment with a Mendelow Influence × Interest grid — engagement quadrant derived (Manage Closely / Keep Satisfied / Keep Informed / Monitor), plus pain points, sentiment, decision authority, POC, and champion.

Produces
SHA xlsx + interactive HTML dashboard (Influence×Interest grid) + sha_records.json
Use it when
  • You need a stakeholder map or engagement strategy from interview notes
  • Leadership asks "who's affected and who can block this?"
  • The comms plan needs audience groups that reconcile with the CIA roles
Example ask
"Build a stakeholder assessment from these interview notes."
Needs
Transcripts, interviews, or stakeholder notes
Feeds
comms-toolkit, persona-journey-builder, change-network-builder, ocm-readout-builder

Deps: openpyxl. Ships validate_chain.py.

Design tom-vro-builder

Turns the CIA into a Target Operating Model + Value Realization approach via a 6-step method (Ingest → Map → Reshape → Prioritize → Surface → Generate) — 8 TOM dimensions, VRO 4-tier model, value streams, and benefits-realization rules (baseline source + owner per KPI).

Produces
TOM Accelerator pptx + TOM Approach docx + VRO Registers xlsx (benefits register + value-at-risk) + TOM dashboard HTML
Use it when
  • The client needs future ways of working shaped from the impact data
  • You're scoping a value realization office or benefits register
  • A pre-sale needs an operating-model accelerator slide fast
Example ask
"Turn this CIA into a target operating model and benefits register."
Needs
cia_records.json (or the CIA xlsx/dashboard) + fit-gap or transcript inputs
Feeds
Program design, VRO stand-up, adoption-metrics-builder (value levers)

Deps: openpyxl + python-pptx + python-docx.

Engage comms-toolkit

Turns the program (ideally its CIA) into a running comms operation — audience segmentation, channel mix + cadence ("What's Changing" email arc, manager cascade 24h/48h, town halls, SteerCo), approval gate with plain-language QA, crisis comms, and ADKAR alignment.

Produces
Comms Master Grid xlsx + 5-tab HTML dashboard + Coverage Matrix xlsx (uncovered impacts flagged GAP) + Markdown vehicle templates + plain-language QA checker
Use it when
  • You need a comms plan or calendar with real cadence, not a blank grid
  • You must prove every change impact has a comm vehicle (coverage + GAPs)
  • Drafts need a plain-language QA gate before they send
Example ask
"Build a comms plan and coverage matrix off our CIA."
Needs
cia_records.json / sha_records.json where available; otherwise plain-language intake
Feeds
ocm-playbook-builder (comms_plan.json seeds activities); drafting + approval workflow

Deps: openpyxl (comms_qa.py is stdlib-only). Ships validate_chain.py.

Engagement & Adoption

Downstream skills that consume the CIA/SHA to run engagement, measure adoption, and brief leadership.

EngageSustain change-network-builder

Designs and runs a change champion network — tiered model, sizing ratios, influence-over-seniority selection, operating rhythm, recognition, and sustainment — with coverage-by-BU analysis and GAP flags.

Produces
Champion roster xlsx + HTML dashboard (coverage by BU/location, GAP flags) + Markdown templates (nomination email, onboarding agenda, monthly touchpoint agenda)
Use it when
  • Setting up or refreshing a champion/change-agent network
  • Leadership needs a nomination process and selection criteria
  • You need to see which BUs/locations have no champion coverage
Example ask
"Design a change champion network for a 3,000-person rollout."
Needs
Network design inputs + roster; BU/location list (SHA groups help)
Feeds
comms-toolkit (champion touchpoints), training-rollout-builder (super-user enablement)

Deps: openpyxl.

Measure adoption-metrics-builder

Builds an adoption & success measurement package using the metric ladder (system usage → behavior/proficiency → process outcomes → business value), leading vs lagging indicators, baseline/target/threshold discipline (no invented targets), RAG, and cadence/ownership.

Produces
Metrics register xlsx + measurement plan + interactive HTML adoption dashboard
Use it when
  • The program asks "how will we know adoption is working?"
  • You need KPIs mapped to CIA value levers with coverage GAPs flagged
  • Go-live is near and there's no measurement plan
Example ask
"Build an adoption metrics framework tied to our CIA."
Needs
Metrics intake; optionally cia_records.json for value-lever mapping
Feeds
ocm-playbook-builder, training-rollout-builder (L3/L4 measurement), readouts

Deps: openpyxl.

Measure readiness-pulse-builder

Two modes. DESIGN builds the pulse instrument — readiness dimensions, anchor + rotating questions from a curated bank, segments, cadence, anonymity plan. ANALYZE takes fielded results and renders a readiness readout with wave-over-wave deltas.

Produces
DESIGN: Pulse Survey Guide xlsx. ANALYZE: Readiness Readout HTML (dimension tiles, dimension×segment RAG heat table, wave deltas)
Use it when
  • You need readiness survey questions with a defensible design
  • Pulse results (csv or aggregates) are back and leadership wants the readout
  • Tracking readiness wave over wave through go-live
Example ask
"Design a change readiness pulse for our five business units."
Needs
Audience segments + cadence (DESIGN); fielded results csv or aggregated numbers (ANALYZE)
Feeds
ocm-readout-builder, ocm-playbook-builder (readiness criteria)

Deps: openpyxl.

DesignEngage persona-journey-builder

Builds change personas, current-to-future journeys, and day-in-the-life narratives with a tiered model (Tier 1 deep persona + journey, Tier 2 lightweight, Tier 3 reference-only) and rationalization criteria — a small operable set, not one persona per role.

Produces
Persona register xlsx + interactive HTML explorer (persona cards by tier, journey maps with emotion curves, before/after day-in-the-life panels)
Use it when
  • The program needs personas or journey maps that trace to evidenced impacts
  • Leaders want a "day in the life, before and after" story
  • Too many roles — you need persona rationalization
Example ask
"Build personas and day-in-the-life journeys from our CIA and SHA."
Needs
Persona intake; cia_records.json + sha_records.json when available
Feeds
comms-toolkit (audience empathy), training-needs-builder, readout storytelling

Deps: openpyxl.

DesignSustain ocm-playbook-builder

Builds the OCM playbook + 90-day tactical plan — six workstreams (leadership, comms, network, training, readiness & measurement, sustainment), 30/60/90 phasing, every activity with an owner, output, and done test, plus cadences and a clean-handoff structure.

Produces
Activity register xlsx + interactive HTML playbook (summary tiles, 30/60/90 swimlanes by workstream, filterable activity table, cadence/governance panel, handoff checklist)
Use it when
  • The engagement needs an OCM workplan or 90-day plan
  • High-severity impacts have no mitigation activity (GAP flags)
  • You're handing the change program to the client team
Example ask
"Build a 90-day OCM playbook for the go-live window."
Needs
Playbook intake; consumes cia_records.json / sha_records.json / comms_plan.json when available to seed activities
Feeds
Program governance and the client handoff

Deps: openpyxl.

DiagnoseEngage ocm-readout-builder

Builds an executive readout from CIA/SHA data — a Change Intensity Map (intensity = volume × depth, derived from the CIA, never hand-scored), a Volume×Depth quadrant matrix, 4-7 executive themes clustered by story, and per-theme who/what/how boards.

Produces
Change Intensity Map HTML + executive readout content (who/what/how impact boards) + leader talking points in a conversational spoken register
Use it when
  • Leadership asks "where does this change hit hardest?"
  • You need readout deck content or a heat map of change
  • Sponsors need spoken talking points, not slideware prose
Example ask
"Build an executive readout and change intensity map from the CIA."
Needs
cia_records.json (+ sha_records.json)
Feeds
Leadership briefings, SteerCo, sponsor enablement

Deps: openpyxl.

Training

A five-step chain (Strategy → TNA → Curriculum → Content + Interactive → Rollout) with an unbroken thread: change impact → training need → module → rollout wave → measurement.

DesignTraining training-strategy-builder

The upstream strategic layer, before the TNA — guiding principles, modality strategy by workforce type (frontline vs office vs field), governance and ownership, super-user multiplier resourcing, build-vs-buy, Kirkpatrick measurement framing, and phasing relative to go-live.

Produces
Strategy-on-a-page register xlsx + interactive HTML strategy document (principles, modality matrix, governance, resourcing, risks/assumptions/open questions)
Use it when
  • The program asks for a training strategy or enablement approach
  • Governance/ownership of training is undecided
  • Unknowns need to become open questions, not invented answers
Example ask
"Draft a training strategy for our ERP program."
Needs
Program context (workforce types, go-live timing, L&D landscape)
Feeds
training-needs-builder and the rest of the training chain

Deps: openpyxl.

DiagnoseTraining training-needs-builder

Step 1 of the training chain. Derives a training needs analysis from the CIA (or raw current/future-state notes) — audience × capability × current/target proficiency × priority × modalities, each need traced to its change impact; flags impacts where formal training is the wrong response.

Produces
training_needs.json + TNA xlsx + HTML dashboard (via needs_render.py)
Use it when
  • You need to answer "who needs to learn what?"
  • Converting a finished CIA into training requirements
  • Separating true skill gaps from mindset/role shifts
Example ask
"Turn our CIA into a training needs matrix."
Needs
cia_records.json, or raw current/future-state notes (runs its own intake without a CIA)
Feeds
curriculum-architect, training-rollout-builder

Deps: openpyxl.

DesignTraining curriculum-architect

Step 2. Turns the needs matrix into a curriculum blueprint — role-based learning paths, sequenced modules with Bloom's-aligned measurable objectives, a 70-20-10 modality blend, prerequisites, and an assessment plan, using backward design (objectives → assessment → content).

Produces
curriculum.json + curriculum xlsx + HTML dashboard (via curriculum_render.py)
Use it when
  • The TNA is done and training must become modules and paths
  • You need real learning objectives, not topic lists
  • Sequencing and prerequisites across roles need structure
Example ask
"Design the curriculum and learning paths from our needs matrix."
Needs
training_needs.json (builds the needs inline if missing)
Feeds
training-content-builder, interactive-learning-builder, training-rollout-builder

Deps: openpyxl.

The interactive twin of content-builder. Builds gamified quizzes (scored, instant feedback, branching, pass badge) and microlearning flashcard decks (flip cards, spaced-repetition-lite) that open from any browser or Drive link and report completion + score inside an LMS.

Produces
Self-contained interactive HTML learning objects; optional --scorm packages a SCORM 1.2 zip for LMS upload with tracking
Use it when

  • Microlearning/flashcards suit the audience better than a deck
  • The LMS needs a SCORM package with completion tracking

Needs
Module objectives/assessment from curriculum.json (same source as content-builder)
Feeds
Delivery / LMS

TrainingSustain training-rollout-builder

Step 4 (Implement & Evaluate). Plans deployment and measurement — delivery waves by BU/location/go-live, schedule and logistics, super-user enablement, learner comms touchpoints, readiness criteria, a Kirkpatrick L1-L4 plan tied to the CIA's value levers, and spaced reinforcement/sustainment.

Produces
rollout_plan.md + rollout xlsx + HTML dashboard (via rollout_render.py)
Use it when
  • The curriculum is set and delivery must be scheduled by wave
  • Training measurement/evaluation needs a Kirkpatrick plan
  • Reinforcement after go-live needs structure (sustainment)
Example ask
"Plan the training rollout across our three go-live waves."
Needs
curriculum.json + training_needs.json (or asks for module list + go-live dates)
Feeds
Program team; adoption-metrics-builder pairs with it for post-training measurement

Deps: openpyxl.

Conventions — apply to every skill in the suite

The chaining contract

CIA roles_impacted ↔ SHA stakeholder_group ↔ comms audiences[].name; comms coverage[].impact ↔ CIA title. Name alignment is what keeps the datasets reconciled.

validate_chain.py

Bundled in cia-builder, sha-builder, and comms-toolkit. Machine-checks schemas and cross-skill name alignment before rendering. Fix every ERROR; review WARNs (drift).

No fabrication

A blank field is correct; an invented score, metric, or coverage row is a defect. Unscored sessions stay unscored; unmapped impacts are GAPs, not something to paper over.

Canonical sources before generating

Renderers and derived artifacts read the canonical *_records.json — never a previously derived artifact. When sources conflict, confirm which is authoritative and reconcile first.

Human decisions are read-only

Persisted human reconciliation/mapping decisions (crosswalks, merge rulings, scope calls) live in their own file that scripts read but never overwrite.

No clobber

Renderers refuse to overwrite existing outputs on re-run unless --force. Incremental updates merge into the canonical JSON via *_merge.py — never rebuild from scratch.

Self-contained folders

Each skill ships everything it needs (SKILL.md + references + scripts + examples). Shared code is copied, not imported, so a skill can be zipped and handed to any practitioner.

QA before done

Validate, render, then open or headless-screenshot the HTML and spot-check against source. Nothing client-specific — examples use "Acme ERP"; branding comes from project.json.
